# Chapter mastery

Mastery is awarded automatically when every required quest in a chapter is complete. Optional and repeatable quests are excluded using FTB Quests' own progression rules. Existing quest progress counts immediately; players do not need to repeat completed quests.

FTB Quests shares progress within teams. Mastery therefore follows the player's current team. Resetting quest progress or changing teams can remove a mastery stage if the current team no longer meets its requirements. The check runs on login and every ten seconds.

## Commands

| Command | Result |
| --- | --- |
| `/mastery` | Your completed chapters only, with a coloured mastery overview. |
| `/mastery player <player>` | The same overview for a selected online player. |
| `/mastery chapter ae2` | Online AE2 masters and completed teams, including offline teams. |
| `/mastery chapter mekanism` | Mekanism mastery holders and completed teams. |
| `/mastery list` | Available chapter keys, including `extendedcrafting`. |

The commands only read quest progress and do not require operator permissions. The server console can use the player, chapter and list forms; the self form needs an in-game player. The player selector targets online players; stored offline completion is listed by team in the chapter form.

Each completed chapter awards a stage named `gspack_mastery_<chapter key>`, such as `gspack_mastery_ae2`. Gaining a new mastery sends one chat notification. Stages are not quest-completion cheats and do not grant items or EMC.

The chapter catalog in `kubejs/data/gspack/mastery_chapters.json` is generated by `tools/build-quests.ps1`. Install it together with `kubejs/server_scripts/gspack_mastery.js`.

The overview hides unfinished chapters. Gold marks headings, green marks mastered chapters and players, and aqua marks completed teams. /mastery list remains the reference for all chapter keys.

Welcome includes a Chapter Mastery explanation quest. All commands are available without OP. Numeric RGB colours avoid Rhino overload ambiguity.
